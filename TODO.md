The server entry point must actually read config, and the refusal text should name the real variables once they work. | open | "Every refusal names its own remedy" is false until this lands. |
| E2 | **Defend stdout at the server entry point.** The package never writes to stdout (enforced by ruff T20 plus an import-time guard), but an *embedder* calling `logging.basicConfig(stream=sys.stdout)` reroutes this library's records onto the MCP protocol channel and corrupts the session. The entry point should install a stderr handler on the package logger and/or refuse to start if a stdout handler is attached. | open | Not fixable inside the library — it cannot see the embedder's config. |
| E3 | **`BULK` is declared and enforced nowhere.** ADR-003 makes it a cross-cutting additive capability, but no gate composes it and there is no helper. Add the composition (`bulk_of(base)` or similar) while there are **zero** call sites to migrate. | open | Cheapest now, most expensive after Block 1's bulk tools. |
| E4 | **A `None` gate means "ungated" and nothing enumerates the set.** With one entry that is readable; with fifty, an accidentally-ungated read is invisible. Make the ungated set explicit and assert it. | open | |
| E5 | **No rate-limit accounting at all** (invariant 9). Retries honour `Retry-After` and a cumulative budget, but nothing tracks the account limit or the much tighter per-endpoint buckets. Incremental export is an order of magnitude stricter. | open | Bites hardest on the export and reporting toolsets. |
| E6 | **`ZendeskClient` will need ~50 `cast(Envelope, ...)` calls.** `PolicyBackend`'s methods are materialised with `setattr`, so mypy sees `Any` through `__getattr__`. Ship a `.pyi`, or give the wrapper an explicitly-typed dispatch handle, before the cast count grows. | open | Decide before the second operation, not the fiftieth. |
| E7 | **`ZendeskClient(bare_backend)` is legal and ungated.** Correct for a library embedder who opted out; wrong for the MCP server, which must never construct one. The entry point needs the assertion the library deliberately does not make. | open | |
| E8 | **`_http.py` has crossed ADR-002's ~400-line tripwire** — 407 lines. OAuth refresh, one of the three known additions, is now delivered (Block 0b). **Rate-limit accounting and pagination-following are still owed, and the split must happen before either lands** — landing more onto a file already over the line only makes the eventual split larger. | open | Crossing the tripwire was a deliberate decision, not an oversight: refactoring the library's hottest code path, unplanned, during a credentials block was judged the larger risk. Plan the split as its own piece of work rather than folding it into the next feature that needs `_http.py`. |
| E9 | **An unpickled `PolicyBackend` refuses with a typed error, but pickling one is meaningless.** Consider a `__reduce__` that refuses outright — a security wrapper arguably should not be picklable. | open | Fails closed today; cosmetic. |
| E10 | **`test_capability_constants_and_the_all_tuple_agree` filters by upper-case name** and will misfire on the first non-capability upper-case constant added to `policy.py`. | open | Well-commented, but fragile by construction. |
| E11 | **No lock file, which ADR-009 explicitly requires** — "written atomically ... under a lock file, because refresh rotates the token and two MCP clients may run the server concurrently." The atomic half exists (temp file + rename); there is no lock at all, and nothing recorded the omission until now. Failure: an MCP server and a probe script both inside the 120s refresh margin both POST the same refresh token; one wins, the other gets `NotAuthorised("run auth login again")` while a valid token sits on disk it never re-reads — or, if Zendesk reuse-detects refresh tokens, the whole chain is revoked and **both** are logged out, intermittently and with no observable correlation between the two failures. | open | Needs a design decision, not an edit. Two cheap mitigations for whoever picks this up: re-read the token file after an `AuthExchangeError` and use the other process's fresh token if it changed on disk; and/or an `O_EXCL` lock file around read-decide-refresh-write. Severity depends on whether Zendesk rotates and reuse-detects refresh tokens on this client type, which the live end-to-end run (F1) will settle. |
| E12 | **`on_invalid_token` has no wirable counterpart in `auth`.** The hook (`_http.HttpClient`'s constructor) must *force* a refresh, but `access_token()` only refreshes inside the 120s margin, and `refresh()` itself is not exported from `auth`. An embedder writing the obvious `HttpClient(token_provider=auth.access_token, on_invalid_token=???)` finds that the retry re-reads the same unexpired-by-the-margin token and gets the identical 401 back, having burned a request for nothing. | open | Needs either `access_token(force=True)` or a documented, sanctioned wiring — whichever is chosen, `auth.__all__` needs to export whatever it is. |
| E13 | **Nothing connects `auth` to the library.** `csa_zendesk/__init__.py` does not export `auth`, and no factory builds an `HttpClient` with `token_provider=auth.access_token`. The two halves — the OAuth module and `HttpClient` — have no documented joint, so the first real consumer has to re-derive it, including running straight into **E12**'s dead end. | open | The MCP server entry point (E1/E2/E7) is the natural place this gets resolved, but it is not resolved yet. |
| E14 | **`NotAuthorised` conflates three different operator remedies**: set an environment variable (`CSA_ZENDESK_SUBDOMAIN`/`CSA_ZENDESK_MCP_SERVER_IDENTIFIER` missing), log in for the first time (no token file), and "your 30-day refresh token expired or was revoked" (a refused refresh). The *messages* distinguish all three; the *type* does not — so a future MCP tool layer that maps exceptions to a `ToolError` category cannot tell them apart without parsing prose. | open | Candidate split: `NotConfigured` / `NotAuthenticated` (already taken by `whoami`'s meaning, so needs a distinct name) / `NotAuthorised` (refresh specifically refused). Not fixed here — a type split is an API change to a public exception, not a "fix wave" edit. |
| E15 | **No revoke path.** `_store.clear()` exists but no CLI command reaches it, and nothing calls Zendesk's OAuth revocation endpoint. "My laptop was stolen" currently means going to Zendesk's admin UI and revoking the client (or the token) by hand; there is no `csa-zendesk auth logout`. | open | A fourth `auth` subcommand, symmetric with `login`. |
| E16 | **Coverage is statement-level, not branch-level.** `pyproject.toml` has no `[tool.coverage.run] branch = true`, so `fail_under = 100` does not mean what a reader of that number assumes — an `if`/`else` where only one arm is ever exercised still reports 100%. The suite very likely already passes with branch coverage on; nobody has checked. | open | Cheap to try: flip it on locally and see what, if anything, it finds before committing to it in CI. |
| E17 | **`auth status` cannot distinguish "expired but fine" from "expired and stuck."** It prints `expired 10 minutes ago` and exits 0 for a token `access_token()` will silently refresh on the next call, exactly the same as it would for a refresh token that has itself expired or been revoked — and it says nothing about the refresh token at all, which is the credential that actually decides whether a browser is needed next. | open | `status` would need to attempt (or at least characterise) the refresh token's own state, which is presently unknowable without spending it. |
| E18 | **Credentials survive in caller frames during a token-endpoint failure.** `_post` scrubs its own frame before raising, but `refresh()`'s `body` dict and `exchange_code()`'s `code` and `verifier` parameters stay bound in their own frames for the life of the call. An error tracker that captures full-stack frame locals — Sentry does this by default — uploads a live refresh token or authorization code to a third party on the first failed exchange. Not reachable today: nothing in this repo configures such a tracker. It becomes reachable the moment one is added, which is a change someone will make for unrelated reasons and without thinking about this. | open | The fix is to pass credentials through as an opaque payload built by a helper that closes over nothing, rather than as plain locals — a design change, deliberately deferred out of Block 0b. `_post`'s own frame scrubbing is already in place (final review fix wave); this is the residue, not the whole risk. |
| E19 | **The local lint gate is narrower than CI's.** Contributors and agents run `ruff check`; CI runs `ruff check` *and* `ruff format --check`, so formatting drift is invisible locally until a pull request. A two-line f-string in `cli.py` drifted from `ruff format`'s preferred single-line join from the moment it was written, survived nine task reviews, a whole-branch review, a fix wave and a re-review — every one of them specified `ruff check src tests` and none ran `ruff format --check` — and was caught only when CI ran on the PR. This block is the evidence, not a hypothetical: a drift introduced in one task survived every subsequent review because no reviewer ran the check that would have shown it. | open | Make one command the gate — a pre-commit hook, or a single documented invocation that runs both `ruff check` and `ruff format --check` — so that passing locally means passing in CI, rather than relying on every task brief to separately remember to name both. |

Recorded so they are not re-proposed as oversights.

- **The six plan-gated families** (IT Asset Management, Group SLA Policies, Workspaces, Ticket
  Form Statuses, Audit Logs, HC Service Catalog Items). Excluded by ADR-001; reopening
  conditions in WAITING-FOR-001. **Audit Logs is the one worth revisiting** if a need appears.

- **Live Chat, Messaging, AI Agents, Sales CRM** — no published spec, post-1.0 or out of scope.
- **Caching.** Both sibling projects deliberately have none; `zenpy` caches by default and that
  is a reason not to build on it, not a feature to copy.
- **An ORM / object mapper.** ADR-002. The seam returns raw envelopes on purpose.
- **A local attachment cache.** One surveyed server has nine tools for it. A local cache of
  customer attachments is a data-retention decision, not a convenience.
- **Naming with a `zendesk_` prefix.** Settled: bare `verb_noun`. The client namespaces already.

- **The Zendesk MCP server written by a CSA colleague.** Asked for during the 2026-09-12 design
  session and **deliberately dropped 2026-09-17**: the prior-art survey exists to learn from servers
  with real adoption, and this one has none. Including it because the author is internal would be
  selecting on relationship rather than on signal, and the aliasing convention exists precisely so
  the survey is about the ecosystem rather than about people. Recorded so it is not re-proposed as an
  oversight.
