# ADR-002: Build the client from scratch; do not chase parity with the official SDKs

**Date:** 2026-08-31
**Status:** Active
**Decision method:** Human decision, AI informed — the build-or-adopt analysis and the
official-client review were supplied; the call was the project owner's.

## Goal

Settle two questions before implementation: whether to build on an existing Zendesk client
library, and how much of the official SDKs' surface to match.

## Context

Full analysis in [`analysis/CLIENT-LIBRARIES.md`](../analysis/CLIENT-LIBRARIES.md) and
[`analysis/OFFICIAL-CLIENTS.md`](../analysis/OFFICIAL-CLIENTS.md). In summary:

- **No official Python SDK exists.** Zendesk maintains PHP and Ruby only.
- `zenpy` is the one active hand-written Python library: 279 endpoints, effectively untyped,
  caches by default, and built around an object mapper.
- `python-zendesk` is generated from the same Support spec we snapshotted: 1173 methods, but
  Support-only, and its pagination is correct exactly where the spec is correct.
- The two official clients **diverge**: 65 resources each, 33 shared, 34% overlap of the union.

## Decision

**Build the HTTP layer and the `Backend` from scratch.** Depend on neither Python library.

**Scope is what we need and can verify**: the families that are in the 1.0 capabilities
(Ticketing, Help Center, Status) *and* confirmed reachable by the access audit. Not the union
of what the official SDKs happen to model.

Mine all four libraries for **specific solved behaviours**, listed in `OFFICIAL-CLIENTS.md` §7 —
the cursor-capable path list, never emitting both pagination styles, detecting pagination style
from the response, reading `details` first on a validation error, treating `503` as retryable.

## Rationale

**The architecture does not want what a client library sells.** `Backend` returns raw upstream
envelopes so that one uniform wrapper can gate every method and fail closed. What a client
library adds is an object mapper — exactly the layer we have deliberately left empty. Adopting
one means unwrapping its objects back into envelopes, or moving the seam above it and losing
uniform gating.

**A generated SDK inherits the defects of the document it was generated from**, and we have
established that this document is wrong about pagination, wrong about error shapes, and missing
about a dozen Help Center families.

**There is no canonical surface to match.** The two official clients disagree about half of
their combined surface, so "what should a Zendesk client expose?" has no settled answer to
defer to. Their union is 97 resources against our 125 families — a floor, not a ceiling.

**What we would actually use from a library is the cheap part**: URL construction, `Retry-After`
handling, rate buckets. `scripts/zd.py` already does auth, requests and error-body preservation
in about forty lines.

## Rejected alternatives

**Build on `zenpy`.** Mature and Zendesk's own docs point at it. But no type information for the
`TypedDict`s structured output requires, caching on by default where both sibling projects
deliberately have none, 7 of ~30 Help Center families, and an object mapper occupying the seam.

**Build on `python-zendesk`.** 1173 generated methods is real value. But Support-only — Help
Center is half of 1.0 — and it does not model `details.base[]`, which our experiment established
is the entire actionable content of a validation refusal. v0.3.1, no repository URL, no stated
maintenance commitment.

**Match the official SDKs' combined surface.** Considered and explicitly declined: much of it is
outside our capabilities, some is untestable here, and their disagreement with each other means
matching them is not the same as matching the API. Deferred to research rather than dropped —
see `TODO.md` A1.

## Implementation

Not yet started. When it is:

- `python-zendesk` is a **free conformance check on our generator** — where its 1173 generated
  signatures and ours disagree about an endpoint, one of us misread the spec.
- Reconsider this decision if Zendesk ships an official Python SDK, if `python-zendesk` grows
  Help Center coverage and a maintenance commitment, or **if our HTTP layer passes ~400 lines**,
  at which point we are writing a client library by accident and should say so.
